# Work Breakdown Structure (WBS)

## 1. Purpose

This Work Breakdown Structure (WBS) organises the University Phishing Awareness Programme Dashboard project into manageable work packages. It defines the main activities and deliverables required to plan the programme, prepare synthetic data, develop the dashboards and validate the final outputs.

## 2. Project Scope

The project demonstrates how project management and data visualisation tools can support a hypothetical university phishing awareness programme.

The project includes:
- Project planning and requirements definition.
- Synthetic project task and cybersecurity awareness datasets.
- Excel project tracking and VBA validation.
- Power BI dashboard development.
- Testing, documentation and GitHub portfolio publication.

The project does not involve real university staff data, live phishing campaigns or actual institutional cybersecurity systems.

## 3. Work Breakdown Structure

### 1.0 Project Planning

**1.1 Define project scope**
- Identify the project purpose and objectives.
- Define the project scope and expected deliverables.
- Document assumptions and limitations.

**1.2 Gather requirements**
- Identify the information needed to monitor project progress.
- Define the key performance indicators (KPIs).
- Determine the required dashboard features.

**1.3 Establish project controls**
- Define task owners and responsibilities.
- Set task priorities, deadlines and milestones.
- Identify project risks and testing requirements.

### 2.0 Data Preparation

**2.1 Develop project tracking data**
- Create a synthetic project task dataset.
- Define task status, priority, due date and completion fields.
- Validate data formats and required fields.

**2.2 Develop awareness metrics**
- Create synthetic staff training and phishing simulation data.
- Organise data by department and reporting period.
- Check data consistency and suitability for analysis.

### 3.0 Excel Project Management Tool

**3.1 Build the task tracker**
- Structure project tasks in an Excel table.
- Configure data validation and status options.
- Apply conditional formatting to communicate progress.

**3.2 Develop VBA automation**
- Create a task-counting macro.
- Create a project task validation macro.
- Test the macros using valid and invalid inputs.

**3.3 Validate project tracking**
- Check task records and progress calculations.
- Confirm that validation identifies errors.
- Record testing outcomes.

### 4.0 Power BI Dashboard Development

**4.1 Develop the project overview dashboard**
- Import the project task dataset.
- Create KPI cards for task counts and completion rate.
- Visualise task status and workstream distribution.
- Display the task schedule and overdue task count.

**4.2 Develop the cybersecurity awareness dashboard**
- Import the awareness metrics dataset.
- Calculate staff training coverage.
- Calculate phishing click and reporting rates.
- Visualise departmental comparisons and monthly trends.

**4.3 Improve dashboard usability**
- Add reporting-period filters.
- Apply consistent titles and formatting.
- Check that visuals respond correctly to user selections.

### 5.0 Testing and Quality Assurance

**5.1 Validate data and calculations**
- Check dataset structure and data types.
- Verify KPI calculations and percentage formatting.
- Confirm that filters update the relevant visuals.

**5.2 Review dashboard presentation**
- Check chart titles, labels and readability.
- Confirm that both dashboard pages display correctly.
- Document limitations and the use of synthetic data.

### 6.0 Documentation and Publication

**6.1 Prepare project documentation**
- Document project objectives and requirements.
- Maintain the test plan, risk register and RACI matrix.
- Explain the dataset structure and dashboard functionality.

**6.2 Publish the portfolio**
- Organise project files in the GitHub repository.
- Add dashboard screenshots and README documentation.
- Review repository links and file references.

## 4. Key Deliverables

| Deliverable | Description |
|---|---|
| Project documentation | Scope, requirements, risks, responsibilities and testing approach. |
| Excel task tracker | Task tracking, progress monitoring and VBA validation. |
| Synthetic datasets | Project tasks and cybersecurity awareness metrics. |
| Project overview dashboard | Summary of task progress, status and deadlines. |
| Awareness metrics dashboard | Summary of training coverage and phishing simulation trends. |
| GitHub portfolio | Organised source files, documentation and dashboard screenshots. |

## 5. Completion Criteria

The project is considered complete when:

- The project tracker and VBA validation macros operate as intended.
- Both Power BI dashboard pages display the required metrics.
- Data validation and dashboard checks have been completed.
- Documentation and screenshots are published in the GitHub repository.
- Synthetic data limitations are clearly disclosed.

## 6. Project Limitations

This is a portfolio demonstration using synthetic data. The metrics are illustrative and should not be interpreted as evidence of actual university cybersecurity performance or the effectiveness of a real phishing awareness programme.
