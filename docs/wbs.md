# Work Breakdown Structure (WBS)

## Project: University Phishing Awareness Programme Dashboard

The project is divided into six work packages. Each work package represents a group of related activities and deliverables.

| WBS ID | Work Package | Key Activities | Deliverable |
|---|---|---|---|
| 1.0 | Project Initiation | Define objectives, scope, stakeholders, and success criteria. | Project charter |
| 2.0 | Planning | Define requirements, schedule, responsibilities, and risks. | Requirements document and project plan |
| 3.0 | Excel Tracker | Structure task data, add dropdowns, create KPIs, and apply conditional formatting. | Excel project tracker |
| 4.0 | VBA Automation | Develop task-counting and data-validation macros; test valid and invalid inputs. | Macro-enabled workbook |
| 5.0 | Power BI Dashboard | Prepare synthetic datasets, model relationships, create measures, and build visual reports. | Interactive dashboard |
| 6.0 | Testing and Closure | Validate calculations, document limitations, capture screenshots, and evaluate outcomes. | Test report and closure report |

## Dependencies

- Project initiation must be completed before detailed planning.
- Requirements should be defined before finalising the tracker and dashboard.
- Excel data structures should be stable before importing them into Power BI.
- Dashboard testing depends on having prepared synthetic datasets.
- Project closure follows implementation and testing.

## Delivery Approach

The work packages will be developed iteratively. Early versions may be revised as testing identifies errors or improvements. Completion will be assessed against the requirements and acceptance criteria.

## Scope Control

Any proposed feature outside the agreed scope should be recorded and assessed for its impact on time, complexity, and deliverables before being added.
